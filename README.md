# PaySim Sandbox

An isolated payment sandbox (REST API + demo UI) that simulates the full payment lifecycle —
create, process, success / failure / timeout, refund — **without any real money or bank connection**.

- **Backend:** Python 3.14, FastAPI, SQLAlchemy, PostgreSQL
- **Frontend:** React, Vite, Tailwind CSS
- **AI:** Google Gemini (debugging assistant + transaction audit summaries)
- **Docs:** [docs/openapi.json](docs/openapi.json) · [docs/compliance.md](docs/compliance.md) · [docs/demo-script.md](docs/demo-script.md)

```
pending ──► processing ──► success ──► refunded
                     ├───► failed
                     └───► timeout
```

## API

| Method | Path | Purpose |
|---|---|---|
| POST | `/api/v1/auth/register` | Create a merchant account → returns your sandbox API key |
| POST | `/api/v1/auth/login` | Sign in → returns a new sandbox API key |
| GET | `/api/v1/auth/me` | The merchant that owns the API key |
| POST | `/api/v1/payments` | Create a payment (`pending`). Requires `Idempotency-Key`. |
| GET | `/api/v1/payments/{transaction_id}` | Current status + audit history |
| POST | `/api/v1/payments/{transaction_id}/refund` | Full refund of a `success` payment. Requires `Idempotency-Key`. |
| POST | `/api/v1/sandbox/smoke-test` | Run the end-to-end smoke test |
| POST | `/api/v1/ai/debug` | Gemini explains a failed API call |
| POST | `/api/v1/ai/audit-summary/{transaction_id}` | Gemini summarises a transaction |

All payment, sandbox and AI endpoints require `Authorization: Bearer sk_test_...`.
Create an account in the UI (or with `/auth/register`) to get your own key, or use the shared demo account.
Interactive docs: `https://127.0.0.1:8000/docs`.

Example:
```bash
curl -X POST https://127.0.0.1:8000/api/v1/payments \
  -H "Authorization: Bearer sk_test_..." \
  -H "Idempotency-Key: 6f1c2b8e-order-1001" \
  -H "Content-Type: application/json" \
  -d '{"amount": "100.00", "currency": "LYD", "reference": "ORDER-1001", "simulation_mode": "force_success"}'
```

## First-time setup (Windows)

Requirements: Python 3.12+, Node.js 20+, PostgreSQL 15+, mkcert.

1. **Backend**
   ```powershell
   cd backend
   py -m venv .venv
   .venv\Scripts\python -m pip install -r requirements.txt
   copy .env.example .env      # then edit .env: DB password, GEMINI_API_KEY
   .venv\Scripts\python scripts\seed.py   # creates the DB + demo merchant, prints the sk_test_ key
   ```
2. **HTTPS certificate** (from the project root)
   ```powershell
   mkcert -install             # trust mkcert's local CA (shows a Windows security prompt)
   mkdir certs; cd certs
   mkcert -cert-file localhost.pem -key-file localhost-key.pem localhost 127.0.0.1 ::1
   ```
   In `backend/.env` set `SMOKE_TLS_VERIFY` to the path of `rootCA.pem` (`mkcert -CAROOT` shows the folder).
3. **Frontend**
   ```powershell
   cd frontend
   npm install
   copy .env.example .env.local   # then paste the sk_test_ key from step 1
   ```

## Run

Terminal 1 — API (from `backend/`):
```powershell
.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --ssl-certfile ..\certs\localhost.pem --ssl-keyfile ..\certs\localhost-key.pem
```

Terminal 2 — UI (from `frontend/`):
```powershell
npm run dev
```
Open **https://localhost:5173**.

## Smoke test from the terminal

From `backend/`:
```powershell
$env:PAYSIM_API_KEY = "sk_test_..."
$env:PAYSIM_CA_FILE = "$(mkcert -CAROOT)\rootCA.pem"
.venv\Scripts\python scripts\smoke_test.py
```
Exit code `0` = all five steps passed.

## Deploy (Render, free)

The `Dockerfile` builds the React UI and serves it from the FastAPI server, so the whole app is one URL.
`render.yaml` creates the web service and a free PostgreSQL database.

1. Push this repository to GitHub.
2. On [render.com](https://render.com): **New → Blueprint** → select the repository → **Apply**.
3. When asked, paste your `GEMINI_API_KEY` (or leave it empty to disable AI features).
4. Wait for the build, then open `https://<service-name>.onrender.com`.

Notes: HTTPS is provided by Render. `DEMO_API_KEY` is generated by Render and built into the UI (it is a sandbox key).
Free services sleep after 15 minutes idle (first request takes ~1 minute), and the free database expires after 30 days.
